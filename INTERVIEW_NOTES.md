# Technical Interview Q&A Guide — AI News Intelligence Agent 🎓

This guide contains clear, technically accurate answers to 23 interview questions about the architecture, fine-tuning, RAG, and engineering trade-offs of the **AI News Intelligence Agent**.

---

### Q1: What problem does the project solve?
**Answer:**
Modern news consumption suffers from information overload, duplicate reporting across media outlets, and clickbait headlines. The **AI News Intelligence Agent** addresses this by:
1. Collecting live news from multiple sources (GNews, RSS).
2. Generating domain-specific structured summaries (Title, Summary, Key Points, Why It Matters, Topics).
3. Grouping duplicate/related coverage from different publishers.
4. Enabling grounded Q&A over current events via RAG.

---

### Q2: Why did you use an LLM instead of traditional text summarizers (e.g. TextRank/LSA)?
**Answer:**
Traditional extractive methods (like TextRank or LexRank) only select existing sentences from the source text, which often results in disconnected or fragmented summaries. Large Language Models (LLMs) perform **abstractive summarization**—they understand context, synthesize key ideas, rewrite complex concepts cleanly, and extract structured fields (like "Why It Matters" or topic tags).

---

### Q3: Why did you fine-tune a model for this project?
**Answer:**
General pre-trained LLMs often produce inconsistent summary styles, overly verbose outputs, or miss structured JSON/markdown constraints. Fine-tuning adapts an open-source model to a specific domain (news summarization) so it consistently generates structured output with consistent tone, brevity, and format without needing complex system prompts every time.

---

### Q4: Why not train a transformer model from scratch?
**Answer:**
Training an LLM from scratch requires billions of tokens, massive GPU clusters, and millions of dollars. Pre-trained models (like Flan-T5 or Llama) already possess rich general language understandings, syntax knowledge, and reasoning capabilities. Fine-tuning leverages **transfer learning** to adapt pre-trained knowledge to our news summarization task using minimal compute and data.

---

### Q5: What is LoRA (Low-Rank Adaptation)?
**Answer:**
LoRA is a **Parameter-Efficient Fine-Tuning (PEFT)** technique. Instead of updating all billions of weights in a pre-trained base model, LoRA freezes the original model weights and injects low-rank trainable decomposition matrices ($W_0 + \Delta W$, where $\Delta W = A \times B$) into target attention layers (like query and value projections). This reduces the trainable parameters by over 99%, making fine-tuning feasible on consumer GPUs or CPUs.

---

### Q6: What is QLoRA?
**Answer:**
QLoRA (Quantized Low-Rank Adaptation) takes LoRA further by quantizing the frozen base model parameters into **4-bit NormalFloat (NF4)** precision while keeping the low-rank adapter weights in higher precision (16-bit float). This dramatically reduces GPU VRAM consumption (e.g. fitting a 7B model in under 6GB VRAM) without sacrificing fine-tuning accuracy.

---

### Q7: What are adapter weights?
**Answer:**
Adapter weights are the small set of trainable parameter matrices ($A$ and $B$) learned during LoRA fine-tuning. Because the base model remains frozen, we only need to save and distribute the adapter weights (typically 5MB–50MB) rather than saving the entire multi-gigabyte base model. At inference time, the adapter weights are loaded and merged onto the base model.

---

### Q8: Why is fine-tuning useful specifically for news summarization?
**Answer:**
News articles have specific domain requirements: objective reporting style, highlight of key metrics, identification of real-world impact, and consistent categorizations. Fine-tuning teaches the model to reliably extract these specific elements in a structured format while adhering to concise word limits.

---

### Q9: Why is the fine-tuned model designated as the PRIMARY model in your architecture?
**Answer:**
The core objective of this project is to demonstrate custom AI model ownership and local fine-tuning expertise rather than relying solely on third-party APIs. The local fine-tuned model represents our primary intelligence engine, demonstrating low-latency, private, self-hosted LLM inference.

---

### Q10: Why do you still have Groq API as a fallback?
**Answer:**
Production systems must be resilient to hardware constraints and system failures. If the user's machine lacks sufficient RAM/GPU memory to load the local model, if the adapter file is missing, or if local inference throws an exception, the system gracefully falls back to Groq API (`llama-3.1-8b-instant`) to guarantee 100% uptime for the Streamlit UI.

---

### Q11: What are embeddings?
**Answer:**
Embeddings are high-dimensional dense vector representations of text generated by neural networks (e.g. `all-MiniLM-L6-v2` produces 384-dimensional vectors). Words or sentences with similar semantic meanings are mapped to vectors that lie close to each other in vector space, allowing mathematical calculation of text similarity.

---

### Q12: What is Cosine Similarity?
**Answer:**
Cosine similarity measures the cosine of the angle between two non-zero vectors in multi-dimensional space:
$$\text{Cosine Similarity}(A, B) = \frac{A \cdot B}{\|A\| \|B\|}$$
Scores range from 0.0 to 1.0 (for non-negative vectors). Higher scores indicate greater semantic similarity between two news articles or between a user query and an article.

---

### Q13: Why use FAISS (Facebook AI Similarity Search)?
**Answer:**
FAISS is an open-source library optimized for efficient vector similarity search and clustering. Brute-force pairwise vector comparison becomes slow as datasets grow. FAISS indexing allows sub-linear or sub-millisecond retrieval of top-k nearest vector neighbors, making real-time RAG search responsive.

---

### Q14: How do you detect duplicate news articles?
**Answer:**
1. Concatenate each article's `Title + Description + Summary`.
2. Compute dense embedding vectors using SentenceTransformers.
3. Compute pairwise cosine similarity between all article vectors.
4. Cluster articles exceeding a configurable similarity threshold (e.g., $\ge 0.75$).
5. Group them into a cluster with a primary headline and a count of related coverage sources.

---

### Q15: What is RAG (Retrieval-Augmented Generation)?
**Answer:**
RAG combines vector retrieval with LLM generation. When a user asks a question, the system searches a vector database to retrieve relevant document snippets, feeds those snippets as context into the LLM prompt, and instructs the LLM to generate an answer grounded strictly in the retrieved context.

---

### Q16: Why use RAG even after fine-tuning a model?
**Answer:**
- **Fine-tuning** updates model *behavior*, *format*, and *style*, but its internal knowledge remains static as of training time.
- **RAG** provides *up-to-the-minute real-time context* from live news feeds.
Combining both gives us a model that produces perfectly formatted summaries while referencing live, non-hallucinated news data.

---

### Q17: How does "Ask About This News" work under the hood?
**Answer:**
1. User enters a natural language question in the UI.
2. `generate_embedding(question)` embeds the question.
3. `search_vector_index(query_vec)` queries FAISS to retrieve the top $K$ relevant news articles.
4. The system constructs a grounded context block containing those articles.
5. The prompt (Context + Question + Non-Hallucination Guardrails) is passed to the LLM.
6. The grounded answer and source citations are displayed in Streamlit.

---

### Q18: How do you reduce LLM hallucinations?
**Answer:**
1. **Strict Prompt System Instructions**: Instructing the model to state "Insufficient information" if context lacks necessary facts.
2. **Grounded Context**: Constraining generation exclusively to retrieved RAG context blocks.
3. **Low Temperature**: Setting `temperature=0.2` or `0.3` to minimize speculative generation.

---

### Q19: How do you evaluate summarization performance?
**Answer:**
Using **ROUGE (Recall-Oriented Understudy for Gifting Evaluation)** metrics:
- **ROUGE-1**: Overlap of unigrams (single words) between generated and reference summary.
- **ROUGE-2**: Overlap of bigrams (two-word sequences).
- **ROUGE-L**: Longest Common Subsequence (LCS) measuring structural flow.
We also perform qualitative human checks on summary readability and key point accuracy.

---

### Q20: Why choose Streamlit for the frontend?
**Answer:**
Streamlit allows rapid prototyping of data science and AI web apps in pure Python. It supports interactive widgets, reactive session state management, caching, and custom CSS without requiring backend REST/GraphQL boilerplate or complex JavaScript frameworks.

---

### Q21: What happens if the local model cannot run due to limited GPU/RAM?
**Answer:**
The system uses modular fallback handling:
1. It catches CUDA Out-Of-Memory (OOM) or import errors gracefully.
2. Sets system status to `⚠️ Fine-Tuned Model unavailable — Groq API Fallback`.
3. Routes summarization requests to Groq API.
4. If API keys are also missing, executes a heuristic extractor so the UI never crashes.

---

### Q22: How would you scale this system for production?
**Answer:**
1. **Vector DB**: Migrate from in-memory FAISS to a persistent vector database (e.g. Qdrant, Milvus, or Pinecone).
2. **Asynchronous Scraping**: Use Celery/Redis for background news fetching and cron indexing.
3. **Model Serving**: Host the fine-tuned LoRA model using vLLM or TGI (Text Generation Inference) behind a FastAPI gateway.
4. **Caching**: Store article embeddings and generated summaries in Redis cache.

---

### Q23: What are the limitations of the current implementation?
**Answer:**
1. **Model Size**: Base model size is kept small (`flan-t5-small` / `flan-t5-base`) for CPU compatibility; larger models (7B/13B) require GPU hardware.
2. **Rate Limits**: Free API tiers (GNews/Groq) impose rate limits under heavy request volumes.
3. **Single Session State**: Current vector index is stored per user session; multi-user persistence would require a shared vector database.
